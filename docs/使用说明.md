## 平台入口

- 当前访问地址：`http://10.86.0.32:4000`
- 如果后续部署端口调整，请以实际访问地址为准。

## 首次使用流程

### 注册与登录

1. 打开平台首页：`http://10.86.0.32:4000`
2. 首次使用点击“注册”创建账号。
3. 注册成功后使用邮箱和密码登录。
4. 登录后进入默认组织与默认项目；后续可根据业务自行创建更多项目。

说明：

- 如果你使用的是管理员分配的账号，可直接登录，无需注册。
- 登录、注册、密码找回等跳转地址都依赖平台配置的外部访问地址，因此请统一从服务器 IP + 端口访问，不要混用 `localhost`。

### 创建项目

项目用于隔离不同系统、业务线或环境的数据。建议按以下方式划分：

- 一个业务系统一个项目
- 不同环境分项目，例如 `prod`、`staging`、`test`
- 不同团队分项目，避免数据混杂

创建方式：

1. 登录后进入右上角用户菜单。
2. 打开 `Settings`。
3. 进入 `Projects`。
4. 点击 `Create Project`。
5. 填写项目名称并保存。

建议命名：

- `jiusi-prod`
- `jiusi-staging`
- `sales-assistant`
- `report-agent`

### 添加用户

如需邀请其他同事使用平台：

1. 切换到目标组织。
2. 进入 `Settings`。
3. 打开 `Members`。
4. 点击 `Invite Member`。
5. 输入成员邮箱并选择角色。

角色建议：

| 角色 | 说明 | 建议用途 |
|------|------|----------|
| `Owner` | 组织最高权限，可管理成员、项目、配置 | 平台负责人 |
| `Admin` | 可管理项目和大部分配置 | 技术负责人 / 运维 |
| `Member` | 可查看和使用大多数功能 | 开发、算法、测试 |
| `Viewer` | 只读查看 | 业务、运营、审计 |

### 创建 API Key

SDK 接入必须使用 API Key。每个项目应使用自己的 Key，不建议跨项目共用。

创建方式：

1. 先切换到要接入的目标项目。
2. 进入 `Settings`。
3. 打开 `API Keys`。
4. 点击 `Create new API key`。
5. 保存生成的 `Public Key` 与 `Secret Key`。

字段说明：

| 字段 | 格式 | 用途 |
|------|------|------|
| Public Key | `pk-lf-...` | 客户端标识，可用于初始化 SDK |
| Secret Key | `sk-lf-...` | 服务端鉴权密钥，必须妥善保管 |

使用建议：

- `Secret Key` 仅放在服务端环境变量中
- 不要把 `Secret Key` 写到前端代码或公开仓库
- 每个项目独立一套 Key，便于隔离和审计

## SDK 接口使用

### 安装与初始化

安装：

```bash
pip install langfuse
```

代码初始化：

```python
from langfuse import Langfuse

client = Langfuse(
    public_key="pk-lf-xxx",
    secret_key="sk-lf-xxx",
    host="http://10.86.0.32:4000",
    timeout=30,
)

client.auth_check()
```

也可以使用环境变量：

```bash
export LANGFUSE_HOST="http://10.86.0.32:4000"
export LANGFUSE_PUBLIC_KEY="pk-lf-xxx"
export LANGFUSE_SECRET_KEY="sk-lf-xxx"
```

初始化参数说明：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `public_key` | `str` | 是 | 项目 Public Key |
| `secret_key` | `str` | 是 | 项目 Secret Key |
| `host` | `str` | 是 | Langfuse 访问地址 |
| `timeout` | `int` / `float` | 否 | 请求超时时间，单位秒 |

输出/效果：

- 初始化成功后返回 `Langfuse` 客户端对象
- 调用 `auth_check()` 成功，说明 Host 与 Key 可用

### 核心概念

| 概念 | 说明 | 常见 `as_type` |
|------|------|----------------|
| `Trace` | 一次完整请求，是整条链路的根节点 | `agent`、`chain` |
| `Span` | 链路中的普通步骤，如检索、规则判断、工具调用 | `span`、`tool` |
| `Generation` | 一次模型调用，记录 prompt、输出、token、耗时 | `generation` |
| `Prompt` | 可复用的提示词模板，支持版本管理 | - |
| `Score` | 对 Trace 或 Generation 的评分 | - |

### 常用接口说明

#### 1. `start_as_current_observation(...)`

用途：创建当前追踪节点，可作为 Trace、Span、Tool、Generation 使用。

常用入参：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | `str` | 是 | 节点名称 |
| `as_type` | `str` | 是 | 节点类型，如 `agent`、`span`、`tool`、`generation` |
| `input` | `dict` / `list` / `str` | 否 | 输入内容 |
| `output` | `dict` / `list` / `str` | 否 | 输出内容 |
| `model` | `str` | 否 | 模型名称，常用于 `generation` |
| `model_parameters` | `dict` | 否 | 模型参数，如 `temperature`、`max_tokens` |
| `prompt` | 对象 | 否 | 提示词模板对象，用于关联 Prompt 版本 |
| `usage_details` | `dict` | 否 | token 统计，常见为 `input` / `output` |
| `metadata` | `dict` | 否 | 自定义元数据 |
| `session_id` | `str` | 否 | 会话 ID，用于多轮会话归组 |
| `user_id` | `str` | 否 | 用户 ID |

输出/效果：

- 进入上下文后自动建立当前节点
- 如果外层已有节点，会自动挂到父节点下面
- 可通过 `client.get_current_trace_id()` 获取当前 Trace ID

#### 2. `client.get_current_trace_id()`

用途：获取当前 Trace 的 ID。

输入：无。

输出：

- 返回当前 Trace 的字符串 ID
- 可用于后续打分、跳转 Web 页面、日志关联

#### 3. `client.update_current_observation(...)`

用途：更新当前节点内容，适合在实际调用完成后补写输出与用量。

常用入参：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `output` | `dict` / `list` / `str` | 否 | 补充输出内容 |
| `usage_details` | `dict` | 否 | 补充 token 统计 |
| `metadata` | `dict` | 否 | 补充元数据 |

输出/效果：

- 当前节点被更新为最新状态

#### 4. `client.update_current_generation(...)`

用途：和 `update_current_observation` 类似，但明确用于模型调用节点。

常用入参：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `output` | `dict` / `str` | 否 | 模型响应 |
| `usage_details` | `dict` | 否 | token 使用量 |

输出/效果：

- 当前 Generation 节点被更新

#### 5. `client.create_prompt(...)`

用途：创建或更新提示词模板。

常用入参：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | `str` | 是 | 提示词名称 |
| `prompt` | `str` | 是 | 模板内容，支持 `{{变量}}` |
| `labels` | `list[str]` | 否 | 模板标签，如 `production` |
| `config` | `dict` | 否 | 模板关联配置，如模型、温度 |

输出：

- 返回 Prompt 对象
- 可读取 `prompt.name`、`prompt.version`
- 可调用 `prompt.compile(...)` 进行变量替换

#### 6. `client.get_prompt(...)`

用途：获取指定名称的提示词模板。

常用入参：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | `str` | 是 | 模板名称 |
| `label` | `str` | 否 | 按标签获取，如 `production` |

输出：

- 返回 Prompt 对象

#### 7. `client.create_score(...)`

用途：为 Trace 或具体节点打分。

常用入参：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `trace_id` | `str` | 是 | 目标 Trace ID |
| `observation_id` | `str` | 否 | 具体节点 ID，给某个 Generation 打分时使用 |
| `name` | `str` | 是 | 评分名称 |
| `value` | `int` / `float` / `str` | 是 | 评分值 |
| `data_type` | `str` | 是 | `NUMERIC`、`BOOLEAN`、`CATEGORICAL` |
| `comment` | `str` | 否 | 备注说明 |

输出/效果：

- 评分写入 Langfuse
- 可在 Trace 详情页和 Scores 页面查看

#### 8. `client.flush()`

用途：主动刷新缓冲区，确保数据已发送到平台。

输入：无。

输出/效果：

- 当前进程内尚未发送的追踪数据被立即提交
- 在脚本退出前建议显式调用一次

### 输入输出格式建议

#### `input` 推荐格式

1. 文本输入：

```python
input="用户输入内容"
```

2. 对话消息：

```python
input=[
    {"role": "system", "content": "你是一个助手"},
    {"role": "user", "content": "帮我总结这段文本"},
]
```

3. 结构化对象：

```python
input={
    "query": "帮我分析最近一周销售趋势",
    "user_id": "u001",
    "filters": {"region": "华东"},
}
```

#### `output` 推荐格式

1. 纯文本：

```python
output="这是模型输出"
```

2. 对话消息：

```python
output={"role": "assistant", "content": "分析结果：本周销售上升 8.3%"}
```

3. 工具返回：

```python
output={"rows_returned": 152, "execution_time_ms": 45}
```

#### `usage_details` 推荐格式

```python
usage_details={
    "input": 256,
    "output": 198,
}
```

#### `metadata` 推荐格式

```python
metadata={
    "user_id": "user-demo-001",
    "latency_ms": 312,
    "app": "sales-assistant",
    "version": "1.0.0",
}
```

要求：

- 尽量使用可 JSON 序列化的数据
- 避免放入超大二进制内容
- 不要在 `metadata` 中写入敏感明文密钥

### 基础追踪示例

```python
from langfuse import Langfuse

client = Langfuse(
    public_key="pk-lf-xxx",
    secret_key="sk-lf-xxx",
    host="http://10.86.0.32:4000",
    timeout=30,
)

with client.start_as_current_observation(
    name="my-llm-call",
    as_type="generation",
    model="qwen2.5-72b-instruct",
    model_parameters={"temperature": 0.7, "max_tokens": 512},
    input=[
        {"role": "system", "content": "你是一个智能助手"},
        {"role": "user", "content": "今天天气怎么样？"},
    ],
    output={"role": "assistant", "content": "请问您在哪个城市？"},
    usage_details={"input": 30, "output": 12},
    metadata={"user_id": "u001", "latency_ms": 450},
):
    pass

client.flush()
```

### 多层嵌套链路示例

```python
with client.start_as_current_observation(
    name="agent-session",
    as_type="agent",
    input={"query": "帮我分析销售数据"},
    metadata={"user_id": "u001"},
):
    trace_id = client.get_current_trace_id()

    with client.start_as_current_observation(
        name="intent-recognition",
        as_type="span",
    ):
        with client.start_as_current_observation(
            name="intent-llm",
            as_type="generation",
            model="qwen2.5-7b",
            input=[{"role": "user", "content": "..."}],
            output={"role": "assistant", "content": "data_analysis"},
            usage_details={"input": 60, "output": 5},
        ):
            pass

    with client.start_as_current_observation(
        name="sql-query",
        as_type="tool",
        input={"sql": "SELECT ..."},
        output={"rows": 152},
    ):
        pass

    with client.start_as_current_observation(
        name="response-generation",
        as_type="generation",
        model="qwen2.5-72b-instruct",
        input=[{"role": "user", "content": "..."}],
        output={"role": "assistant", "content": "分析结果：..."},
        usage_details={"input": 256, "output": 198},
    ):
        pass

client.flush()
```

### 提示词模板示例

```python
prompt = client.create_prompt(
    name="intent-classifier-v2",
    prompt="将用户输入分类为：{{categories}}\n\n用户输入：{{user_input}}\n\n请直接返回类别名称。",
    labels=["production"],
    config={"model": "qwen2.5-7b", "temperature": 0.1},
)

prompt_obj = client.get_prompt("intent-classifier-v2")
compiled = prompt_obj.compile(
    categories="data_analysis, alert_config, help",
    user_input="设置每天早 9 点发送日报",
)

with client.start_as_current_observation(
    name="classify",
    as_type="generation",
    model="qwen2.5-7b",
    prompt=prompt_obj,
    input=[{"role": "user", "content": compiled}],
    output={"role": "assistant", "content": "alert_config"},
    usage_details={"input": 64, "output": 5},
):
    pass

client.flush()
```

client.create_score(

### 方式四：在 Scores 页面查看评分

- 评分名称
- 评分值

## Web 端关键模块说明

### Traces（链路追踪）

用途：查看完整调用树，是排查问题的首选入口。

常见操作：

- 查看输入 / 输出
- 查看耗时与 token
- 查看 metadata
- 按时间、用户、标签、评分过滤

### Sessions（会话）

用途：按 `session_id` 聚合同一会话的多轮 Trace。

适用场景：

- 多轮聊天
- 工单流转
- Agent 长链路任务

### Generations（模型调用）

用途：专门查看所有模型调用。

重点信息：

- 模型名称
- prompt / output
- token 用量
- 成本估算
- 延迟分布

### Scores（评分）

用途：统一查看人工评分和自动评分。

适用场景：

- 人工质检
- 幻觉检测
- 准确率评估
- 排序和筛选问题样本

### Prompt Management（提示词管理）

用途：管理提示词模板与版本。

重点能力：

- 模板版本历史
- 标签管理
- 模板变量渲染预览
- 查看某版本关联的 Trace

### Datasets（数据集）

用途：沉淀评估样本和 Golden Set。

适用场景：

- 评测数据集管理
- 从线上 Trace 回捞样本
- 对比不同 Prompt / 模型效果

### Evals（自动评估）

用途：配置自动打分规则。

可用于：

- 忠实度评估
- 相关性评估
- 安全性评估
- 大规模自动质检

### Dashboards（仪表盘）

用途：查看总体趋势与统计。

常看指标：

- 请求量
- 模型用量
- 延迟
- 错误率
- 评分趋势

### Settings（系统设置）

重点关注：

- `Projects`：项目管理
- `Members`：成员与权限管理
- `API Keys`：Key 管理
- `Models`：模型定价与成本估算配置

## 常见问题

### 1. 注册成功后跳转到 localhost

原因：平台外部访问地址配置仍然是 `localhost`。

处理方式：

- 将 `NEXTAUTH_URL` 配置为实际访问地址，例如：`http://10.86.0.32:4000`
- 重启服务使配置生效

### 2. 脚本执行成功，但 Web 中看不到 Trace

排查顺序：

1. 确认 `LANGFUSE_HOST` 是否正确
2. 确认使用的是当前项目对应的 API Key
3. 确认脚本末尾调用了 `client.flush()`
4. 在 `Traces` 页面按最新时间筛选

### 3. 应该给哪个项目创建 Key

原则：哪个项目接入，就给哪个项目创建 Key。

不要：

- 多个业务系统混用一套项目 Key
- 在测试环境复用生产项目 Key

### 4. `input` 和 `output` 应该传什么

推荐传可读、可检索、可复盘的数据：

- 用户请求
- 系统提示词
- 模型输出
- 工具调用参数与结果
- token 用量与关键 metadata

避免传入：

- 无意义的大对象
- 明文密码、密钥、令牌
- 无法序列化的二进制对象
