### 核心概念

| 概念 | 说明 | 对应 `as_type` |
|------|------|----------------|
| **Trace** | 一次完整的用户请求，是链路树的根节点 | `"agent"` / `"chain"` |
| **Span** | 链路中的一个处理步骤（检索、工具调用等） | `"span"` / `"tool"` |
| **Generation** | 一次 LLM 模型调用，记录 prompt/output/token 用量 | `"generation"` |
| **Score** | 对一条 Trace 或 Generation 打分（人工/自动） | — |

所有节点均通过 `start_as_current_observation()` 上下文管理器创建，自动形成父子树。

---

### 基础追踪

```python
# 单次 LLM 调用追踪
with client.start_as_current_observation(
    name="my-llm-call",
    as_type="generation",
    model="qwen2.5-72b-instruct",
    model_parameters={"temperature": 0.7, "max_tokens": 512},
    input=[
        {"role": "system", "content": "你是一个智能助手"},
        {"role": "user",   "content": "今天天气怎么样？"},
    ],
    output={"role": "assistant", "content": "请问您在哪个城市？"},
    usage_details={"input": 30, "output": 12},
    metadata={"user_id": "u001", "latency_ms": 450},
):
    pass   # 实际调用在此处完成

client.flush()   # 确保数据发送
```

### 多层嵌套链路

```python
with client.start_as_current_observation(
    name="agent-session",
    as_type="agent",
    input={"query": "帮我分析销售数据"},
    metadata={"user_id": "u001"},
):
    trace_id = client.get_current_trace_id()

    # 第一步：意图识别
    with client.start_as_current_observation(
        name="intent-recognition",
        as_type="span",
    ):
        with client.start_as_current_observation(
            name="intent-llm",
            as_type="generation",
            model="qwen2.5-7b",
            input=[{"role": "user", "content": "..."}],
            output={"role": "assistant", "content": "data_analysis"},
            usage_details={"input": 60, "output": 5},
        ):
            pass

    # 第二步：工具调用
    with client.start_as_current_observation(
        name="sql-query",
        as_type="tool",
        input={"sql": "SELECT ..."},
        output={"rows": 152},
    ):
        pass   # 实际查询在此处

    # 第三步：生成回答
    with client.start_as_current_observation(
        name="response-generation",
        as_type="generation",
        model="qwen2.5-72b-instruct",
        input=[{"role": "user", "content": "..."}],
        output={"role": "assistant", "content": "分析结果：..."},
        usage_details={"input": 256, "output": 198},
    ):
        pass

client.flush()
```

在 Web UI 中，以上三步会显示为树形链路，可逐层展开查看每步的输入输出和耗时。

### 提示词模板管理

```python
# 创建/更新提示词模板（支持 {{变量}} 占位符）
prompt = client.create_prompt(
    name="intent-classifier-v2",
    prompt="将用户输入分类为：{{categories}}\n\n用户输入：{{user_input}}\n\n请直接返回类别名称。",
    labels=["production"],          # 标签：production / staging / latest
    config={"model": "qwen2.5-7b", "temperature": 0.1},
)

# 在调用时关联模板，Langfuse 自动记录版本信息
prompt_obj = client.get_prompt("intent-classifier-v2")
compiled   = prompt_obj.compile(
    categories="data_analysis, alert_config, help",
    user_input="设置每天早 9 点发送日报",
)

with client.start_as_current_observation(
    name="classify",
    as_type="generation",
    model="qwen2.5-7b",
    prompt=prompt_obj,          # 传入 prompt 对象，自动关联版本
    input=[{"role": "user", "content": compiled}],
    output={"role": "assistant", "content": "alert_config"},
    usage_details={"input": 64, "output": 5},
):
    pass

client.flush()
```

### 打分与评估

```python
# 对一条 Trace 打分（数值型，范围 0–1）
client.create_score(
    trace_id=trace_id,
    name="user-feedback",
    value=0.9,
    comment="回答准确，有参考价值",
    data_type="NUMERIC",
)

# 布尔型打分
client.create_score(
    trace_id=trace_id,
    name="is-hallucination",
    value=0,
    data_type="BOOLEAN",
)

# 对某个具体 Generation 打分（需要 observation_id）
client.create_score(
    trace_id=trace_id,
    observation_id=generation_id,
    name="faithfulness",
    value=0.85,
    data_type="NUMERIC",
)

client.flush()
```

## Web 端关键模块说明

登录后，左侧导航栏提供以下主要模块：

---

### Traces（链路追踪）

**路径：** 导航栏 → 可观测性 → 链路追踪

**用途：** 查看所有请求的完整调用链路，是最核心的调试入口。

**关键操作：**
- 点击任意一条 Trace，进入树状视图，可展开每个 Span/Generation 查看：
  - 输入内容（Input）/ 输出内容（Output）
  - 耗时（Latency）/ Token 用量
  - 关联的评分（Scores）
  - Metadata 自定义字段
- 顶部过滤栏支持按 **时间范围**、**用户 ID**、**标签（Tags）**、**评分** 筛选
- 右侧面板可查看 **JSON 原始数据**

---

### Sessions（会话）

**路径：** 导航栏 → 可观测性 → 会话

**用途：** 将同一用户的多轮对话 Trace 归组，还原完整对话流程。

**使用方式（SDK）：**
```python
with client.start_as_current_observation(
    name="multi-turn-chat",
    as_type="agent",
    session_id="session-user001-20260506",   # 相同 session_id 的 Trace 自动归组
    user_id="user-001",
):
    pass
```

---

### Generations（模型调用）

**路径：** 导航栏 → 可观测性 → 模型调用

**用途：** 汇总所有 `as_type="generation"` 的节点，专注于 LLM 调用的分析：

- **Token 用量统计**：按时间/模型/用户汇总 input/output tokens
- **成本估算**：自动匹配模型定价表，计算 API 调用费用
- **延迟分析**：p50 / p90 / p99 延迟分布
- **模型对比**：不同模型在同类任务上的表现对比

---

### Scores（评分）

**路径：** 导航栏 → 可观测性 → 评分

**用途：** 管理所有已记录的评分，包括手动标注和自动评估结果。

**评分类型：**
| 类型 | 说明 |
|------|------|
| NUMERIC | 数值型（0–1 或自定义范围） |
| BOOLEAN | 是/否 布尔型 |
| CATEGORICAL | 枚举型（如 good / bad / neutral） |

**手动在 UI 标注：** 在 Trace 详情页 → 点击 **Add score** → 填写分数和备注

---

### Prompt Management（提示词管理）

**路径：** 导航栏 → 提示词管理

**用途：** 集中管理所有提示词模板，支持版本控制和 A/B 测试。

**核心功能：**
- **版本历史**：每次 `create_prompt` 自动新增版本，可回滚
- **标签管理**：`production` / `staging` / `latest` 三类标签，SDK 可按标签拉取
- **变量预览**：点击模板可预览 `{{变量}}` 插值后的渲染结果
- **关联 Traces**：点击某个版本，可看到所有使用了该版本的 Trace 列表

**按标签拉取最新生产版本（SDK）：**
```python
prompt = client.get_prompt("my-prompt", label="production")
```

---

### Datasets（数据集）

**路径：** 导航栏 → 数据集

**用途：** 管理用于评估和微调的样本数据集。

**核心功能：**
- 创建数据集，上传 input/expected_output 样本对
- 将线上 Trace 一键加入数据集（用于构建 Golden Set）
- 对数据集运行评估实验（Experiments），对比不同 Prompt 版本

**快速将 Trace 加入数据集（UI）：** Trace 详情页 → 右上角菜单 → **Add to dataset**

---

### Evals（自动评估）

**路径：** 导航栏 → 评估

**用途：** 配置基于 LLM-as-Judge 的自动评分流水线，无需人工标注。

**工作流程：**
1. 在 **Evaluators** 中新建评估器，选择评估维度（faithfulness / relevance / toxicity 等）
2. 关联数据集或实时 Traces
3. 配置评估使用的模型（支持 OpenAI / 自定义端点）
4. 查看自动评分结果，筛选低分 Trace 重点分析

---

### Dashboards（仪表盘）

**路径：** 导航栏 → 仪表盘

**用途：** 提供开箱即用的统计图表，无需手动建表。

**内置图表：**
| 图表 | 说明 |
|------|------|
| Trace Volume | 每日/每小时请求量趋势 |
| Model Usage | 各模型 Token 用量对比 |
| Latency Distribution | P50/P90/P99 延迟分布 |
| Score Overview | 各评分维度均值趋势 |
| Error Rate | 失败请求占比 |
| User Activity | 活跃用户数量 |

可通过右上角时间选择器切换 **7天 / 30天 / 自定义** 范围。

---

### Settings（系统设置）

**路径：** 右上角用户头像 → Settings

**关键子页面：**

| 子页面 | 说明 |
|--------|------|
| **API Keys** | 创建和管理 Public/Secret Key 对 |
| **Members** | 邀请团队成员，设置角色权限（Owner / Admin / Member / Viewer） |
| **Models** | 自定义模型定价，用于 Cost 估算 |
| **Integrations** | 第三方集成（Slack 告警通知等） |
| **Data Retention** | 配置 Trace 数据保留周期 |
| **Projects** | 多项目管理，每个项目独立 API Key 和数据隔离 |

## 与 jiusi-claw 后端集成

### 方式一：手动追踪（推荐）

在后端 LLM 调用处加入 `start_as_current_observation` 上下文：

```python
# backend/app/services/llm_service.py

from langfuse import Langfuse

langfuse = Langfuse()   # 自动读取 LANGFUSE_* 环境变量

async def generate_response(user_id: str, messages: list) -> str:
    with langfuse.start_as_current_observation(
        name="generate-response",
        as_type="generation",
        model=settings.LLM_MODEL,
        input=messages,
        metadata={"user_id": user_id},
    ):
        result = await llm_client.chat(messages)
        langfuse.update_current_observation(
            output={"content": result.content},
            usage_details={
                "input":  result.usage.prompt_tokens,
                "output": result.usage.completion_tokens,
            },
        )
        return result.content
```
